# dsh-remote-access 3.2

桌面 DSH 的手机远程访问插件。支持独立设备配对、局域网直连、自建中转及 DeepSeek Harness `0.2.1-rc.5` 的 Typert 协议适配。服务器端只有后端，不需要管理网页。

设置页使用 DeepSeek Harness 的主题控件，中英文随宿主语言切换。

## 构建与打包

在整个仓库根目录运行：

```sh
npm ci --legacy-peer-deps
npm run build
npm run build:client
npm test
npm pack
```

宿主提供 Cordis 和 DSH 服务，WebSocket 和本地二维码生成依赖随本包的 npm 依赖安装。`cordis.patch.yml` 注册宿主插件和客户端设置面板。安装需将生成的 tgz 加入目标 DSH profile。

## 使用流程

- 直连：点击“添加 → 直连”，手机填写可访问的电脑 DSH 地址，再选择六位配对码或电脑确认。
- 中转：按 [后端说明](https://github.com/WILSONowo/dsh-remote-backend) 准备支持自动注册的服务器。插件“远程控制 → 服务器”填写 HTTPS 地址，保存服务器设置，等待连接成功。
- 开启“允许连接”，点击“添加 → 服务器连接”，手机首页扫码或粘贴临时连接信息，然后在电脑确认。二维码两分钟有效、一次使用，重新生成会使旧二维码失效；每台手机单独配对，互不共用凭证。
- 主机 ID 和注册凭证自动创建并持久保存。电脑名称默认读取系统设备名，可在设备列表重命名；已配对手机也可独立重命名，随机身份与配对凭证不变。不再接受手填主机 ID 或注册凭证；后端需更新至 2.0.0。旧手动中转须重新填写服务器地址并启用，手机删除旧记录后重新扫码。
- 直连支持电脑生成六位配对码或本机确认。服务器中转只接受有效临时连接信息，须经电脑确认；手机必须持有发起请求时生成的随机秘密才能领取凭证。
- 从旧版升级需要重新配对；旧共享通道令牌不再接受。

## 鉴权边界

每台手机使用独立随机令牌，桌面只保存令牌摘要。`pair/check` 只验证当前凭证，不能按设备 ID 领取令牌。直连配对码十分钟过期，五次错误锁定，使用后作废。撤销、重新配对和轮换令牌会关闭该设备已有 HTTP/WS/SSE 连接，其他设备不受影响。

生成配对码、批准请求、设备管理、公网域名白名单和中转配置只允许本机管理请求。检查 socket 来源、Host、Origin、跨站标记和代理头；中转内部请求有不可通过 HTTP 伪造的标记，不能凭 localhost 获得管理权限。原生桌面浏览器继续使用宿主鉴权。

中转是可信服务器，可看到终止 TLS 后的流量；当前不是端到端加密。配对的手机拥有远程控制权限，包括已有文件操作辅助功能，请只批准自己的设备。

## API 与持久化

配对：`/api/remote-access/pair/{request,status,respond,claim,check,list,revoke}` 和 `pair/code/{generate,current,verify}`。设备自己可调用 `token/{rotate,revoke,audit}`；管理员可撤销指定设备。

中转：本机 `GET/POST /api/remote-access/relay/config`。GET 不返回注册凭证。保存于 `$DSH_HOME/remote-access/relay.json`；设备摘要保存在 `devices-v2.json`，电脑身份和名称在 `identity.json`。不要复制这些私密文件给另一台电脑，克隆身份会造成连接冲突。配置写入失败不会返回成功凭证。

本机 `POST /api/remote-access/relay/pairing` 生成二维码和临时连接信息，不包含长期注册凭证。手机以一次性 ticket 调用 `pair/request`，电脑批准后再凭手机请求秘密领取独立凭证。仅允许电脑本机生成二维码，服务器不代替电脑批准手机。

业务适配由 `modern.ts` 实现，经宿主 Gateway 校验参数及创建调用作用域。每个手机事件连接有自己的 Peer，审批应答与设备和连接相关联，不能代答其他设备的请求。旧宿主不挂载此适配层。

`sync` 不执行离线任务，提交的离线操作明确返回 `offline_execution_not_supported`，避免把未执行的操作报告为成功。其他文件、设备信息及 MCP 辅助路由保留。

更多迁移信息见 [协议说明](https://github.com/WILSONowo/dsh-remote/blob/main/docs/protocol.md)，可选测试配置见 [测试说明](docs/testing.md)。

## 连接与唤醒

- “允许连接”同时控制直连和服务器连接。关闭会断开现有远程连接，使未完成的配对失效，保留已配对设备与服务器配置。
- 设备的最近连接时间来自成功认证的访问；旧记录没有历史时间时显示“暂无连接记录”。活动时间最多约 30 秒合并写入一次。
- 重命名本电脑时，点击“重置”再保存可恢复系统设备名，设备身份及配对不变。直连支持地址二维码，也可填写公网隧道地址生成二维码；扫码后仍需配对码或电脑确认。
- “保持电脑唤醒”目前支持 Windows：仅在接通电源且允许连接时请求防止自动睡眠，不强制亮屏，不修改电源计划，也不会阻止用户手动睡眠。使用电池、关闭选项、关闭远程连接或退出插件时释放请求；其他系统显示不可用。
- 更新插件后，请完整退出 DeepSeek Harness（包括托盘后台）再启动，以确保界面与后台使用同一版本。如果提示“连接设置接口不可用”，先重启；仍未恢复时重新安装完整插件包。“重试”只会重新读取设置，不会重启后台。
- 直连地址来自本电脑网络接口，手机仍需能够访问对应端口。公网隧道的可信域名可在“其他设置 → 可信域名 → 管理”中配置。

## 局域网配对码直连

电脑打开「远程控制 → 添加 → 配对码直连」，设备在「添加电脑 → 配对码直连」中搜索并选择电脑，再输入六位码。多台设备各自重新生成配对码，已有设备的凭证不受影响。

插件仅在配对窗口中通过 mDNS/DNS-SD 发布 `_dsh-pair._tcp`，使用 DSH 实际服务端口；关闭页面、停止允许连接、码过期或配对完成后停止发布。页面失去联系后最多 30 秒停止。广播包含显示名称、临时发现标识及候选地址，不包含配对码、访问凭证或持久电脑身份。

发现需要局域网允许 mDNS（UDP 5353）及访问 DSH 服务端口；访客网络、隔离网段或防火墙可能阻止发现。插件不自动修改防火墙。发现失败时可改用 IP 直连或扫码，IP 直连仍支持域名和内网穿透。此功能无需服务器后端修改。
